# Shumora 1.3.5

This update improves terminal responsiveness, installation recovery, loading feedback, and Council language handling, and adds optional skill discovery and in-app update notifications.

Release-note scope: commits `dc6ffc9` through `ab6f762`, inclusive. Notes describe the final behavior at the end of this range; the temporary local-theme feature was removed before this release.

## Terminals and performance

- Improve terminal clipboard shortcuts while preserving Ctrl+C as an interrupt when no text is selected. Handle copy and paste once per key press and report clipboard failures.
- Improve terminal fitting and resize handling, including when terminal panes become visible again.
- Optimize bounded terminal history storage to avoid repeatedly copying the entire scrollback buffer as output arrives.
- Skip redundant workspace-state writes when persisted terminal metadata has not changed, while saving actual tab changes immediately.
- Load optional sidebar pages on demand and provide page-level error recovery.
- Allow WebAssembly compilation in the renderer Content Security Policy for components that require it, without enabling arbitrary JavaScript string evaluation.

## Library and tool installation

- Allow longer package-manager operations, with a 15-minute default installation timeout and a bounded `SHUMORA_INSTALL_TIMEOUT_MS` override.
- Include the executable, timeout, and termination reason in installation diagnostics.
- Verify Pi installations after successful package-manager changes and report conflicting executables on PATH or in `PI_EXECUTABLE` instead of silently using a different installation.
- Look for supported global Pi installations when the application's inherited PATH does not yet contain their executable directory.
- Refresh installation status after a failed command and improve recovery and operation-output feedback when returning to plugin details.
- Remove the experimental Add-ons tab and local JSON theme import, preview, and management. Appearance settings retain built-in light, dark, and system modes.

## Loading and interface feedback

- Match model-loading skeletons to the model table layout rather than displaying unrelated placeholders.
- Show themed skeletons while lazy-loaded sidebar pages are being prepared instead of a plain loading message.

## Skills

- Report loaded agent skill counts through the meeting bridge.
- Offer an optional skill-discovery prompt when an agent reports no loaded skills, with actions to browse skills, dismiss the suggestion, or hide it permanently.
- Keep skill installation optional; the suggestion does not install packages automatically.

## Application updates

- Check for application updates on startup when the updater is idle.
- Show a dismissible in-app notification when a new version is available or an update is ready to install, with a link to the update page.
- Avoid overwriting newer update events with an older initial status response.

## Council

- Instruct Council participants to follow the language of the discussion topic instead of forcing the application's UI language.
- Support informal and mixed-language topics, using the predominant conversational language rather than technical terms or file paths.
- Honor the user's latest explicit language-change request in subsequent replies and the final summary.
- Use the UI language only as a fallback when a topic has no identifiable language, such as a bare URL or file path.
- Keep Council discussion-only: language preferences do not authorize tools, file changes, or task execution.

## Maintenance and limitations

- Add terminal-history benchmarks and Linux performance smoke-test scripts, expand regression coverage, and refresh dependency lockfile metadata.
- Pi Windows installer installations remain distinct from verified global package-manager installations; this release does not add installer-based update or uninstall support.
- Council language behavior is guided by model instructions; provider and model behavior may vary.
- Preparing version 1.3.5 does not itself publish installers or a GitHub Release. Platform availability depends on the release workflow and target-platform validation.
