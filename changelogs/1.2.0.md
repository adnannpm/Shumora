# Shumora 1.2.0

Changes since Shumora 1.0.0.

## Library

- Replace persistent package and plugin update banners with a compact update badge in the Library header. Hide the badge when no updates are available.
- Combine package and plugin update checks and retain the result when switching Library tabs, avoiding repeated checks on category changes.
- Show only categories that contain updates in the update dialog, with a count for each category and direct access to package or plugin details.
- Keep failed checks discoverable from the header and show their details without reporting that everything is up to date.
- Keep manual update checking available as a quiet secondary action. Confirm an empty manual check without restoring a persistent banner; omit the redundant “Update check complete” message when the badge already shows available updates.
- Align Library controls, typography, spacing, borders, surfaces, and small corner radii with Shumora Settings and application chrome in light and dark themes.
- Use consistent package and plugin grids and more compact cards. Preserve uniform preview slots, contain images without cropping, and keep missing or broken-image fallbacks.
- Arrange search and filters into deliberate rows on narrower windows instead of leaving the sort control on an isolated row.
- Fix early image failures resetting package previews and streamline package update interactions.

## Terminals and workspace

- Restore saved terminal entries and workspace layout when reopening Shumora. Restored terminals start new processes; running processes and terminal output are not persisted across exit.
- Display structured Pi agent activity and unread indicators on terminal tabs.
- Notify when an agent completes or fails while Shumora is in the background, with a saved notification preference in Settings.
- Support inline terminal images through the xterm image addon.
- Soften split-pane controls and dividers to better match the workspace theme.

## Council

- Add reusable Council role management in Settings and use saved roles when configuring discussions.

## Source control

- Add Git push from the source-control interface.
- Use command-style action labels and align source-control actions with application theme colors and interaction states.

## Settings, language, and platform integration

- Add Simplified Chinese interface translations alongside English and Indonesian.
- Consolidate Settings sections and add safe Pi diagnostics for troubleshooting.
- Fix automatic appearance mode to follow the native operating-system theme.
- Add Windows Explorer folder integration and improve the Windows Pi launcher.

## Release reliability

- Validate release builds across Linux, Windows, and macOS before merging release changes.
- Improve cross-platform Git test fixtures, Windows path comparisons, and Windows integration-test timing.

## Requirements and limitations

- Pi still requires a separate installation and configured model-provider access. Package and plugin changes may require stopping active sessions first.
- Restoring workspace entries does not resume a previous process or restore its terminal scrollback.
- Council participants use their own model access and credits. Review recommendations before executing them.
- Commit-message generation sends the staged diff to the selected model through 9router; review sensitive changes before using it.
- Preparing this version does not publish installers or a GitHub Release. Signing and platform availability depend on the release workflow configuration.
