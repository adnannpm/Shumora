# Shumora 1.3.0

This release improves terminal setup, expands tool management, and brings provider quotas and credit balances into the 9router dashboard.

Release-note scope: commits `4975dac` through `bb6c760`, inclusive.

## Terminals and workspace

- Restore interactive xterm scrollbars so terminal output can be navigated with the pointer again.
- Add a terminal-tab context menu and make the workspace toolbar adapt better to narrower windows.
- Show terminal startup progress and guide users through tool setup instead of leaving launch preparation unexplained.
- Support choosing Pi or an installed OpenCode for new terminal sessions. Close all terminal tabs before switching agents; existing sessions are not converted to another agent.
- Align setup controls, surfaces, and translations with the application's light and dark themes.

## First-run setup

- Guide users through choosing installation tools, setting up Pi, checking the 9router integration, and opening their first terminal.
- Open relevant plugin or package details directly from setup so installation actions can be reviewed before approval.
- Verify the required `pi-9router-ext` extension before completing the current Pi setup flow. Installing the local 9router gateway remains optional.
- Distinguish extension checks in progress from verification failures and offer a retry action.
- Keep OpenCode unavailable in the first-run setup selector while retaining its separate terminal-agent setting for installed users.

## 9router dashboard

- Add **Quota & Usage** with account summary cards, provider and plan details, last-checked timestamps, and provider-reported reset windows.
- Add account search and filters for low quota, refresh failures, and disabled connections.
- Show remaining quota and credit balances with progress bars when a percentage or usable total is available. Use green above 50%, yellow from above 20% through 50%, and red at 20% or less remaining.
- Keep balance-only credits visibly unscaled when providers do not report a total. Do not estimate unavailable balances or combine unrelated provider quotas.
- Limit each account card to three model entries initially, with expand/collapse controls and an internally scrollable full list.
- Preserve the last available quota data when a refresh fails and explain when cached data is being shown.
- Refine the Overview layout, API-key table, provider cards, connection filters, and provider-creation dialog.
- Make the model catalog more compact with a searchable, provider-filtered table, inline routing-alias controls, and pagination.
- Use consistent loading skeletons across dashboard pages. Keep the complete quota data area in its loading state until all account requests finish, including during refresh.

## Dashboard sign-in and sign-out

- Redesign the 9router sign-in dialog with a local-endpoint label, clearer password guidance, and a more prominent primary action.
- Add password visibility controls, Caps Lock feedback, initial password focus, and pending sign-in feedback.
- Clear submitted passwords and provide recoverable, credential-safe authentication errors.
- Ask for confirmation before signing out. Cancelling keeps the session; failed sign-out attempts remain in the dialog with a retryable error.
- Clarify that signing out ends the dashboard session in Shumora without stopping 9router or removing provider accounts.

## Library and tool management

- Add ownership-aware detection and management for supported runtimes and package managers, including Node.js, OpenCode, pnpm, Bun, and Yarn. Available actions depend on how a tool was installed and whether Shumora can safely manage it.
- Unify tool-detail pages and installation feedback, including operation output and installation status.
- Add plugin search and category filters.
- Preserve cached package results during background refresh instead of clearing the catalog while new data loads.
- Reuse accessible, theme-aware checkbox controls across the interface.

## Settings and troubleshooting

- Add guarded cleanup for supported tool caches, with measured sizes, confirmation, and actual freed-space feedback. Stop active terminals and installation operations before cleanup.
- Improve the cache overview and explain which tools do not yet support safe cleanup. Conversations and settings are not cleanup targets.
- Simplify terminal diagnostics into a focused Pi launch check with guidance for missing or failing installations.
- Improve support-report copying, including a manual-copy fallback, and remind users to review reports before sharing them.
- Add the official Shumora website link and accessible icons to the About section.
- Update Indonesian and Simplified Chinese translations for the new workflows.

## Security fixes

- Harden Git credential prompts and protect askpass helper handling.
- Require HTTPS for remote AI-provider endpoints while retaining supported local development endpoints.
- Add safeguards against secret disclosure during AI-assisted commit-message generation.

## Requirements and limitations

- Coding agents still require their own installation and configured model access. Installing Shumora does not include provider subscriptions or credits.
- The first-run guide currently supports Pi; OpenCode selection is available separately when installed. Pi-specific extension and Council behavior should not be assumed to work identically with OpenCode.
- Quota availability, units, credit totals, and reset windows depend on the provider. Missing data is not a zero balance.
- Hidden terminal sessions continue running. Restarting a terminal starts a new process and does not guarantee conversation resumption.
- Diagnostic checks do not validate provider authentication or successful model requests. Security safeguards do not replace reviewing sensitive diffs and reports before sending them elsewhere.
- Preparing version 1.3.0 does not publish installers or a GitHub Release. Signing and platform availability depend on the approved release workflow and target-platform validation.
